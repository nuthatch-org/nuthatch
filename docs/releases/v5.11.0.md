Nuthatch 5.11.0 is a cold audit of 5.10.0 put right: 19 defects found by five readers on 2026-10-23,
three of them high, every one fixed with a test that fails without it (#2353). There is no storage
migration, and no existing nest's NID or data identity changes. Several behaviours are stricter, and
the ones that need an operator's attention before upgrading are listed at the end.

## The admin API needs a token, always

A localhost nest with no `NUTHATCH_ADMIN_TOKEN` used to admit any admin request whose `Host` was
loopback. A reverse proxy sends exactly that by default (nginx's `proxy_pass`, Apache without
`ProxyPreserveHost`), so a nest exposed through the nginx recipe in our own docs answered mount,
unmount and reclaim to anyone (#2354).

There is no token-less branch any more. With the variable unset, a localhost nest or runtime makes a
token on first start, 32 random bytes, in `<dir>/.admin-token`, created owner-only (0600) and reused
on later starts. The startup log prints the admin URL with it, and `nuthatch watch --dir` reads it.
A token set in the environment still wins. The file is not part of the nest's identity, bundle or
publication. `nuthatch control` now refuses to start without `NUTHATCH_CONTROL_TOKEN`.

## Identity

- **A symlinked input is refused** (#2355). The identity hash skipped symbolic links while config
  loading followed them, so two nests whose linked `nuthatch.toml` differed only in `start_block` got
  one NID and could share a dataset. `dev`, runtimes, address-history nests, `bundle`, `publish`,
  `migrate` and `init --from` now refuse a linked input by name. A linked `segments/` or
  `nuthatch.redb`, data on another disk, is still fine.
- **A quarantined segment no longer moves the identity** (#2363), and re-importing an unchanged label
  set, list or compliance pack no longer does either (#2368).
- **`migrate`'s adopt copies only derived state** (#2362), so a file the new version deleted stays
  deleted, and the move refuses unless the result computes the planned NID.
- **`nest load` and `pull_by_nid` recompute the installed nest's NID** (#2369) rather than trusting
  the manifest's name and file order.
- **The time-lapse tool's identity is the node's** for nests that decode traces or calls (#2361).

## Reorgs and sealing

- **A live mount's catch-up handles reorgs** (#2371). Mounting, moving or remounting a dataset whose
  tip had been reorged either failed after 64 tries with a misleading error or, past finality depth,
  sealed the orphaned rows. It now runs the same reorg check as the tip loop before fetching.
- **`--seal-direct` seals `threshold_flag` rows** (#2372), as the tip path always did, and cuts its
  segments where the tip path cuts them; the two now produce identical segments. Existing segments
  are not rewritten.

## Address history

- **A deposit-sweep window is held to one chain** (#2360). Behind several RPCs or a load balancer, a
  window's bodies, logs and anchor could come from different forks, and a fork's deposits were
  recorded. Parent links, log block hashes and transaction block hashes are now checked, and a window
  that fails is refused and retried, recording nothing.
- **An unwatched account stays unwatched** (#2367); a relay re-ask that finished after `/api/unwatch`
  wrote its rows back.

## Serving

- **`/diff` refuses `top` above 1,000** (#2356), by name, on the route, the MCP tool and the CLI. An
  unbounded `top` could hold every movement in range or overflow.
- **`/diff` reads its head in the same snapshot as its rows** (#2357), so a block committed during a
  request is not served as an empty story.
- **The address-history `/diff` takes `/sql` permits and a 30 s deadline** (#2358): 503 when busy,
  504 over budget.
- **Webhooks lose nothing under backlog** (#2359). A full outbox used to be trimmed behind the
  webhook's cursor, dropping deliveries and queued compliance alerts without a log line. Webhooks now
  fill at most half the outbox, hold their cursor when it is full, and queue a block too large for
  the room in pieces.
- **A webhook that cannot work refuses the nest at start** (#2365): a `table` or `where` that does not
  bind, or an unknown `since`, named by field. It used to be accepted and never fire.
- **`/ready` serves `tip` and `lag_blocks` as null** until a cursor first polls (#2342), as it does for
  a `serve`-only role; a 0 read as "at the tip".
- **The request ring keeps a name only when the nest declares it** (#2364), so caller-typed text is
  never shown on `/_admin/requests`.
- **In a `graph` build, GraphQL honours a bounded mount's SQL surface** (#2366).
- **The head-count receiver's per-day key cap holds** for made-up version strings (#2370).

## Compatibility and upgrade

Replace the binary and restart. A 5.10.0 store is used as it is. Before upgrading:

- **Anything that calls `/_admin`, the lifecycle routes or the control plane without a token gets
  401.** Set `NUTHATCH_ADMIN_TOKEN`, or read `<dir>/.admin-token` after the first start. Set
  `NUTHATCH_CONTROL_TOKEN` before starting `nuthatch control` (#2354).
- **A nest with a symlinked input file refuses to start.** Replace the link with a copy (#2355).
- **A `[[webhooks]]` entry whose `table`, `where` or `since` cannot work refuses the nest.** The error
  names the field (#2365).
- **`--top` above 1,000 is refused** by `nuthatch diff`, `/diff` and the MCP tool (#2356).
- **A nest that declares `[flags] threshold` and backfills with `--seal-direct` now seals a
  `threshold_flag` table** (#2372). Its NID is unchanged; a dataset sealed before keeps its history
  without flags until re-indexed.
