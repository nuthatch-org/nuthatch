Nuthatch 5.6.2 changes how the release is built, not what it builds. The binaries are the same code as
5.6.1 apart from a test. There is no storage migration.

## The release builds in parallel

Each target used to link its default, scaled and graph binaries one after another in one job, so a tag
took the sum of three fat-LTO links: 2 h 21 min for 5.3.1, the Mac default link alone 87 minutes.
Each (target, variant) is now its own job, so a tag takes the slowest single link plus the image
(#2068, #2035). The asset names are unchanged.

The Mac build moves from `macos-14`, which GitHub retires on 2 November 2026, to `macos-15` (#2037).
The binaries keep the fat `dist` profile: it makes them 34-35% smaller than the thin build, 93.9
against 143.7 MB on Apple Silicon and 114.4 against 168.2 MB on x86_64 Linux (#2036).

## A yanked dependency

The zip crate's maintainers yanked every release but 9.0.3 over flaws in extracting archives
(zip-rs/zip2#1075). dbsp 0.320 depends on zip 6.0.0, but only to write profile archives; nothing in
nuthatch extracts one, so the binary is not exposed. `deny.toml` records that, to be removed on the
next dbsp upgrade, which moves to zip 9 (#2070).

## Gated on Lodestar's data

No query path changes, so this release changes nothing the release gate measures.

## Compatibility and upgrade

Replace the binary and restart. A 5.6.1 store is used as it is.
