Nuthatch 5.10.0 adds `nuthatch watch`, a read-only view of a running nest (RFC-0069), and takes
Burrmill forward four releases: a budgeted engine reads 2,048 rows at a time where it read 128, and an
address is 20 bytes inside a plan rather than 42 characters. There is no storage migration, and no
nest's NID, data identity, registry hash or sealed segment changes.

## Watching a nest

`nuthatch watch [URL]` reads `/ready`, `/`, `/metrics` and `/nests` and nothing else. Piped, it
writes one logfmt line per nest per interval, every number taken from the endpoint in the same read
and `NO SIGNAL` where a source is missing. On a terminal it draws the engine room: the tip, the press,
the boiler, the feed lines and reorgs, one room per cursor when pointed at a runtime, each under its
own chain's tip. `--ssh host` opens a tunnel, `--nest` picks from `~/.config/nuthatch/watch.toml`,
and `NO_COLOR` is honoured. It is behind a default-on `watch` feature; `--no-default-features` removes
it and nothing else. The Linux binary grows by about 0.5 MiB.

Two server additions feed it. `GET /_admin/requests?since=<seq>` returns the last 256 requests per
nest (route template, declared name, status, milliseconds, bytes; never query text), gated exactly as
the admin page and not routed with admin off. `nuthatch_nest_last_reorg_depth_blocks` and its
timestamp gauge appear once a nest has rolled back.

## Burrmill

- **Batches of 2,048 rows under a budget.** Since #1650 a budgeted session read 128 rows at a time, to
  bound a wide-cell projection; that cost every heavy view 1.7 to 2.1 times its time.
- **Addresses as fixed binary.** Between the scan and the answer an `address` column is
  `FixedSizeBinary(20)`; a host sees the text it wrote. Literals of either case compare as addresses,
  statistics still prune, and any text context sees the text. A value in an address column that is
  not `0x` and forty hex digits turns this off for the engine and the statement answers over text.
- **Shared subqueries.** One too large for the pool is run afresh for each reader, and one whose
  first reader stopped early is finished for the others; both had panicked inside DataFusion's
  repartition.

On the release gate's allocations copy, against 5.9.0 under production's budget: p99 1.51 s against
2.54 s, peak RSS 937 MiB against 1,227, no answer different. The QoS copy: p99 1.56 s against 2.28 s.
