Nuthatch 5.12.1 is a security release. It stops a nest's offchain manifest from naming a file outside
the nest's own `offchain/segments/` directory. There is no storage migration, and no nest's NID,
registry hash or sealed segment changes.

## An offchain manifest names only its own files

A nest's `offchain/manifest.json` is an authored input and travels inside a bundle. Each offchain
snapshot names its Parquet file, and that name was joined to `offchain/segments/` without a check, so
an absolute path or a `..` path made `/sql` read a Parquet file outside the nest. In a runtime that
mounts nests from other people, one nest could read another dataset's sealed segments if it knew
their file name.

`offchain::load` now refuses a manifest unless every table name uses the same characters allowed in a
mount alias, and every snapshot file is a plain name ending `.parquet` under `offchain/segments/`. A
snapshot file that is a symbolic link is refused too. The names nuthatch writes itself,
`<table>-<hash>.parquet`, are unaffected, so no nest built by `nuthatch offchain` needs changing.

Who is affected: an operator who mounts nests or bundles written by someone else. A self-hoster
running only their own nests is not exposed, but should upgrade.

## Compatibility and upgrade

Replace the binary and restart. A 5.12.0 store is used as it is. A nest whose manifest names a file
outside `offchain/segments/` now fails to load with the offending table and file named.
