Nuthatch 5.22.0 is for a firm that has to show its own onchain figures to someone else: an answer
as of a block or a time, recipes for an issuer's own token, and an evidence bundle that another
machine re-executes to the same rows. There is no storage migration. No sealed segment and no
registry hash moves. A nest that holds a label set gets a new NID and data identity once, because
label sets are no longer part of what a nest is, and one factory configuration that silently lost
events is now refused at load.

## Upgrade guidance

Replace the binary and restart. A 5.21 store is used as it is.

- **A nest with a label set imported**: its NID and data identity move once, since `labels/` and
  `labels.manifest.json` no longer count toward either (#2946). A single-nest directory starts as
  before. A runtime whose mount record was written with labels present logs `identity drift` for it
  and keeps serving the `data/<nid>` the record names. A nest that publishes writes a full copy under
  the new data identity on its next `publish sync`; the old prefix can be deleted once it lands.
  The operators guide's
  [data lifecycle](https://github.com/nuthatch-org/nuthatch/blob/main/docs/operators.md#data-lifecycle)
  section has the detail.
- **A nest whose `[[factories]]` give one announcing event's `child_param` two templates**: it is
  refused at load, naming both (#2958). It loaded before, but a child takes one template, so the
  second template's tables stayed empty. Declare one template whose ABI holds both contracts' events.
- **A `/sql` client that rejects unknown provenance keys**: an answer may now carry `labels_sha256`
  when it read `labels`, and `segments_sha256` when it was asked at a block.
- Every other nest: nothing to do.

## As of a block or a time

- **`/at?time=T`** places a unix time against the nest's own stamped blocks: the last block at or
  before it, the next one after, and whether that is final, which it is once the next block is
  sealed (#2941). On EURC, 1,000 random times
  from deployment to the tip were all placed with no indexed event between `block` and
  `next_block`, so the nest's state at the time is its state at `block`.
- **`/sql` takes `at_block` or `at_time`** and answers from the rows at or below that block, sealed
  and hot (#2942). Label sets bind as imported now (#2962).

## For an issuer's own token

- **`nuthatch recipe add frozen`, `outstanding` and `mint_burn_daily`** for a FiatToken-style
  contract (#2943). `outstanding` is total supply less frozen balances and the balances of addresses
  labelled `treasury`. Asked at 2022-12-31 23:59 PT on EURC, it gives 24,905,662.05 against the
  24,905,662 of Circle's December 2022 report.
- **`nuthatch recipe add fiat_threshold`** lists transfers above a fiat amount at their UTC day's
  rate, from an offchain table, to recipients in none of the given label sets (#2945). A day with no
  rate lists its transfers as unpriced rather than leaving them out.
- **`examples/mica-art22`** computes the four MiCA Art 22(1) figures over EURC, each deduction of the
  EBA's RTS as its own view (#2947). It is a worked example, not regulatory advice.

## Evidence bundles

- **`nuthatch evidence make "<SELECT>" --at-block N | --at-time T`** asks a running nest for one
  answer as of a sealed block and writes a bundle: the chain, NID, registry hash, statement, rows, a
  hash of the rows in canonical order, the label set's hash when the rows read `labels`, and a hash of
  the final segments they were read from (#2944, #2961). `--key` signs it with a pack key. It refuses
  an unsealed block, and one whose segments include a provisional tail.
- **`nuthatch evidence verify b.json --url <nest>`** asks a nest of the same NID the same statement
  at the same block and says `match`, or names the field that differs. `--dir` re-hashes the
  verifier's own segment files first, which `serve` does not, and names any that changed.
- **Label sets are not part of a nest** (#2946). They seal no byte, the mirror does not copy them,
  and deleting one leaves every chain table and the NID as they were.

## How it was checked

A bundle made on one machine's EURC nest verified on another against a clone seeded from the public
mirror, run with `serve` and no RPC. A fresh full index of the same nest sealed the same 13,133 final
segments through block 26,000,000, byte for byte. [nuthatch-org/eurc-nest](https://github.com/nuthatch-org/eurc-nest)
is that nest, and its README is the walkthrough.
