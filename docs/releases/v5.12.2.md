Nuthatch 5.12.2 is a security release. It stops a bundle from reaching files outside itself when it
is verified and installed. There is no storage migration, and no nest's NID, registry hash or sealed
segment changes.

## A bundle installs only its own regular files

A bundle is untrusted input: a registry mount, `POST /_admin/bundles` and `nuthatch nest load` all
unpack one and check every file against its manifest before installing it. Unpacking accepted any
tar entry type, so a bundle could carry an entry that resolved to a file elsewhere on the host. The
integrity check then read that file, its error could name the file's hash or whether a path existed,
and the install copied it into the nest. On a runtime that mounts nests from other people, a nest
could install another dataset's sealed segment this way and read it through its offchain tables, so
the offchain checks in 5.12.1 do not cover it. Such an entry could also make the check read without
end.

Unpacking now admits only regular files and directories, and the integrity check refuses a manifest
file reached through a link. A manifest path that names derived state in any letter case is refused
too, since a case-insensitive filesystem, such as the default on macOS, would otherwise install it
as the dataset's own derived files.

Who is affected: anyone who loads or mounts a bundle they did not build. Bundles written by
`nuthatch nest bundle` hold only regular files and are unaffected.

## Compatibility and upgrade

Replace the binary and restart. A 5.12.1 store is used as it is. A bundle holding a link, a device or
another special entry now fails to load, naming the entry.
