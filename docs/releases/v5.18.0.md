Nuthatch 5.18.0 is the release that fixes what the cold audit of 2026-11-06 found (tracker #2676):
67 issues filed from seven scopes and three readers, and the follow-ups they led to, in 69 pull
requests since 5.17.0. It adds no feature. It includes 5.17.1 and 5.17.2 (#2662, #2663, #2669),
which are not described again here. There is no storage migration, and `arrow`, `parquet` and
Burrmill are the versions 5.17.2 shipped. **Some nests move identity, and a nest with a Solidity
`function` event parameter must re-index**, so read the next section before upgrading.

## Before you upgrade

**These nests get a new NID.** What that costs depends on what moved, and each item says so.

- **A nest with a row-driven `[[calls]]` declaration** (#2697). Editing a call's `args`,
  `signature`, `on`, `on_any`, `contract_column` or `canonical` used to leave the decode identity
  where it was, so `dev` accepted the store and wrote rows under the new reading beside rows under the
  old one, in one table. Those fields now feed the decode hash, and the store records identity
  formula 3. A formula-2 store whose hash matches today's config is adopted once, with a warning:
  formula 2 cannot see these fields, so a store whose call was edited before the upgrade is adopted
  under the edited reading, and the warning says so. After that one adoption, an edit to what a call
  reads is refused like any other change to what the nest decodes. A sampled declaration keeps its
  hash. The nest's `schema.json` carries the decode hash, so it is rewritten on the next start and
  the NID moves with it. A nest whose calls were not edited is not re-indexed.
- **A nest with an event that has a Solidity `function` parameter** (#2694), such as
  `Callback(function target)`. The parameter was stored as null, at the top level and inside tuples
  and arrays, and rebuilding the row on the reorg and entity paths failed on the null. A top-level
  `function` column is now `fixed_bytes` holding the 24 bytes of address and selector; inside a tuple
  or array it renders as `0x` hex. History is not re-decoded: such an event marks the registry hash,
  so the nest moves identity and its old null rows are refused rather than served beside new ones.
  **Re-index such a nest.** Every other nest's registry hash is unchanged.
- **A nest whose `chain` the registry does not know, over a `chain_id` it does** (#2686), now
  refuses to load, naming the registry's chain. It used to run on the unregistered policy (depth-64
  finality and a 20-block log window) without a word. Rename `chain` to the name the message gives;
  that changes the NID. `init --chain arbitrum-mainnet` and similar provider names now adopt the
  registry entry when the RPC's chain id is registered, keeping the caller's RPCs and saying which
  name it used.
- **Three changes to what counts as a nest's input.** A `.gitignore`, at any depth, is no longer
  hashed (#2722), so a nest that had one gets a new NID, the one it would have had without it. That is
  a new number only: a hidden file was never in the data identity, so its data is kept. A `checkpoints`
  directory is left out only at the root, in every build (#2740): before, a `graph` build left out
  every directory of that name and a default build left out none, so one directory had two NIDs. And
  a nest file that is not UTF-8 is refused by name (#2739), where the node hashed its bytes and the
  engine its replacement characters.

**These are refused where they used to be accepted.**

- **`nuthatch add` on a nest that has indexed** (#2685). It used to append the contract and leave the
  next `dev` to exit 1 on the changed decode registry. It now opens the store first and refuses
  before writing anything, naming both ways on: move `nuthatch.redb` and `segments/` aside to
  re-index every contract, or index the new contract as a nest of its own with the exact `init` line.
- **An address-history request whose `endblock` lies past `end_block`** (#2734), Etherscan's usual
  `endblock=99999999` included, now answers `NUTHATCH_INCOMPLETE: history ends at block E`, as a
  `startblock` past it already did. It used to say the blocks were being backfilled and to ask again
  later, which could never come true. A request naming no `endblock` is unchanged.
- **A live mount that asks for a failover mirror** (#2713), from the request, its record or the
  runtime's default, is refused with 409 before anything is written. It used to answer 200 with no
  publisher running and no writer lease taken. The lease is only taken at boot: declare it in
  `mounts.toml` and restart. A plain mirror still mounts live.
- **A `[[factories]]` `child_param` that is not an address parameter of its event** (#2699) is
  refused, naming the event's parameters. Such a factory discovered no children, silently.
- **`init --from` on a directory holding a symbolic link** (#2692) refuses it rather than copying
  whatever it pointed at.
- **A release tag whose commit is on neither `main` nor its own `release/<major>.<minor>` branch**
  (#2741). The `release-notes` job refuses it before anything else runs.

**These behave differently.**

- **Under `isolation = "strict"`, a mount's `/metrics` carries only its own series** (#2714): the
  samples labelled with that mount and its entity and snapshot series. Before, every mount served the
  whole runtime's exposition, other tenants' mount names and contracts included. The root `/metrics`
  still carries everything, and a shared runtime is unchanged.
- **Verify a release with the workflow and tag pinned** (#2741). `gh attestation verify --repo
  nuthatch-org/nuthatch` accepts an attestation from any workflow on any ref of the repository. The
  commands in `README.md`, `docs/install.md` and the release workflow now add
  `--signer-workflow nuthatch-org/nuthatch/.github/workflows/release.yml` and
  `--source-ref refs/tags/<tag>`; use them.
- **Container images go out after the publish gate and are attested** (#2735, #2736). `:latest` moves
  only for the highest plain `vX.Y.Z`, never for a pre-release or an older line's patch.
- **A `getLogs` range with no answer within the client timeout now narrows** (#2671, #2693).
  Measured on 2026-11-10 against GraphOps' mainnet endpoint, USDC with no topics: 750 blocks answered
  in 49 s and 1,000 in 41 s, with no status line before then, and 2,000 got Cloudflare's 524 at
  125 s. Nuthatch's 20 s client timeout counted that as transient, made one split, retried the halves
  at the same width and aborted the backfill. A header-phase timeout on `eth_getLogs` over more than
  one block is now a narrowable refusal, bounded by the window: an endpoint that never answers is
  asked once per halving and then stops on that block's own timeout. At one block, a stalled body is
  now retried rather than reported as "block N alone exceeds the provider's getLogs result cap",
  which ended the solo loop or quarantined a runtime nest. `eth_call` and header batches are
  unchanged.
- **Malformed Arrow IPC is refused before arrow reads it** (#2811, #2814). arrow-ipc 59.3.0 panics
  rather than errs on a dozen malformed schema shapes and on bad buffers past them. A hostile
  `attach` in a `POST /sql` body could therefore take the engine down, and the tab is built
  `panic=abort`; the follower's feed reader in the binary decodes network IPC with the same reader. A
  check now walks every frame, the schema and each batch's nodes and buffers first, and refuses only
  what the reader would panic on. Found by the new `attach_ipc` fuzz target within a minute.

## Indexer and RPC

- **A one-block window whose overlapped request is refused as too large is asked block by block**
  (#2679, #2751), in `backfill_direct`, `index_loop`, a live mount's `catch_up` and the factory
  seal-direct backfill. It used to end the run as a block over the cap.
- **The tip loops learn a provider's range cap** (#2700). Without `--seal-direct`, a sparse contract
  behind a capped provider grew its window fourfold after each empty answer and paid about two
  refusals per committed window for the whole backfill; on 200,000 empty blocks against a 10,000-block
  cap, 47 refusals for 27 windows. The same run now makes at most one refusal per four windows.
- **A `getLogs` answer is trimmed to what was asked** (#2695). A log past the range, or from an
  address or topic the filter did not name, was stored and its transfer deltas folded, then folded
  again by the next window, so `/balances` stayed wrong. Such logs are dropped with a warning.
- **A header batch answering one block twice is refused** (#2702), rather than one answer standing in
  for a missing one.
- **Window headers, call bodies, `l1_blocks` rows, pinned reads and log timestamps are checked
  against the window's hash set** (#2678, #2754). A pool split across a reorg could seal one fork's
  blocks under another's checkpoint. A missing block body now refuses the window instead of recording
  no calls.
- **A null `eth_getCode` is an error** (#2698), not "no code", which let `init` record a deployment
  block after the real one. **A malformed block-range message is not a result cap** (#2696). **A
  failed RPC body is read only up to its cap** (#2701). **A non-hex proxy storage word reads as no
  proxy** (#2690), where `init` could panic or record a bogus implementation.
- **`nuthatch metadata fetch` does not cache a failed call** (#2720) as permanent empty metadata; a
  revert is still an empty answer.

## Sealing and durability

- **A seal pin that contradicts the stored checkpoint is refused** (#2708). On a chain using the
  finalized tag, a reorg finalized while a window was processed could overwrite the window's
  checkpoint, seal the old fork's rows and prune them. The seal now also checks that its newest row
  is still on the source's chain, and either refusal leaves the next poll to roll the fork back.
- **Seeded segments, mirror writes and registry writes are durable** (#2705, #2709, #2710, #2711).
  Five writers renamed into place without fsync, so a power cut could leave a watermark past rows
  that were never on disk. All go through two helpers that fsync the file and its directory. This was
  proven by the tree's fsync-order trace, not against a real power cut.
- **Registry prune deletes a ref only while it is unchanged** (#2711, #2712): under a lock on a
  filesystem registry, and by an `If-Match` put of an empty tombstone on S3 and R2. A publish that
  re-pointed the ref in between used to lose it. A store without conditional writes now fails the
  prune rather than racing.
- **A shared segment that does not hold the bytes being sealed is replaced** (#2704). A second
  dataset sealing over a rotted shared file catalogued it and pruned its own rows, losing them in
  both datasets.
- **Warm-standby promotion fsyncs, hashes and name-checks each segment** (#2706) before its
  catalogue is installed.
- **`nuthatch.toml` is replaced atomically** (#2688), and `rename-alias` puts the ABI back when the
  save fails.

## Runtime and tenancy

- **One broken nest no longer stops a runtime's boot** (#2680, #2745). An unloadable nest or a
  missing data directory is quarantined beside the others, its mount record kept; a panic while one
  nest is built is caught and becomes that nest's terminal quarantine, with the message.
- **An async mount resumed after a restart keeps its SQL limits** (#2681), and **a mount that fails
  while another joins its dataset no longer deletes that dataset** (#2682).
- **Failover declared on a shared dataset's second mount takes the writer lease** (#2707). Two
  mounts asking for failover at different mirrors are refused at boot.
- **Unmounting a shared dataset's first mount hands the default mirror to the mount left** (#2715),
  where the mirror used to freeze until a restart.
- **A rename the runtime abandoned is left unapplied on both cursors** (#2716), so the runtime and
  cursor no longer disagree on a dataset's name and its mount can still be unmounted.
- **An unloaded mount is kept off `nuthatch_cursor_live`** (#2755), which reported a chain named
  `unknown`.
- **One dead alert or webhook sink cannot starve the rest** (#2718). Each sink drains on its own,
  probed by its oldest entry; a 5xx, timeout or refusal marks it down.
- **HTTP serving cuts off a request body idle for 30 s and holds at most 256 connections per
  listener** (#2724). **A cancelled hot-store scan keeps its SQL permit until it ends** (#2717). The
  public-bind warning names the configured SQL concurrency (#2729), and `operators.md` describes the
  admin token rather than a Host rule that no longer exists (#2721).
- **`nuthatch migrate` keeps each mount record on a rerun** (#2677), with tenants apart; keeps a
  refused nest mounted (#2684); finishes a cross-device copy by rename (#2689); and refuses a staged
  alias two tenants both mount (#2749).

## Address history

- **An undecodable `Transfer`, `TransferSingle` or `TransferBatch` log is skipped** (#2683), counted
  in `nuthatch_address_history_skipped_logs_total`, where it stalled that address's history for good.
- **A `TransferBatch` of more than 65,536 ids fits** (#2747): a token row's element has 32 bits.
  Rows already stored keep their positions.
- **A 429 waits and retries at the same width** (#2730), three times, instead of halving the shared
  window; a topic-only refusal is named.
- **One relay that cannot be asked leaves its blocks unrecorded and re-asked** (#2731), rather than
  failing every produced-block window; and **the MEV pass serves requests and polls while it waits on
  a relay** (#2732), where a slow relay sent `/ready` to stalled.
- **Off a loopback bind, `getblocknobytime` answers from verified headers only** (#2733) and never
  searches the operator's RPC for a caller.

## SQL and verify

- **The `/sql` text gates read Burrmill's own tokens** (#2728), so a comment marker inside a string,
  or a comma join to a file path, no longer slips past them. Burrmill refused every case, so nothing
  was exploitable.
- **`rand()` is volatile in the answer memo** (#2725). `ORDER BY rand() LIMIT 10` kept its first rows
  until the next commit.
- **An authored view over a factory's `__children` works on a fresh session** (#2723) and sees the
  request's hot rows. **A cold reader and `/sql` each keep their analytics session** (#2727), and **a
  refused statement puts its session back** (#2726).
- **A non-ASCII view name no longer panics** (#2703), which stopped `check` and, in a runtime, every
  nest's startup.
- **`nuthatch audit report` refuses a dataset it cannot answer** (#2719), rather than report zero
  flags, and refuses a nest with no `[flags] threshold`.
- **`verify` names a mirror's hydrated blocks as `mirror_unchecked`** (#2738), rather than calling
  them verified; follows views and entities to the tables under them, and says not computable for a
  statement that does not parse (#2737); and hydrates a mirror only to the answer's block, so an older
  answer can be checked (#2742).

## CLI and config

- **`nuthatch check` fails on a config `dev` refuses at load** (#2687), with the same error. It used
  to skip every bind check and exit 0.
- **`init` and `add` write a `.gitignore`** (#2722) for the store and the admin token; `add` leaves an
  indexed nest's alone.
- **`nuthatch watch --ssh` in line mode reopens a dropped forward** (#2691), as the screen mode did.

## CI and fuzzing

- **Four new fuzz targets** (#2743): `cid_car` and `subgraph_manifest` in `fuzz/sql`, and a new
  `fuzz/embed` crate with `header_chain` and `attach_ipc`. CI runs the first three; `attach_ipc` is
  built but not yet run there. `attach_ipc` found #2811 within a minute, and ran clean for 120 s
  (887,349 runs) after the fix.
- **The weekly mutants run finishes green** (#2758): `seal.rs`, at about 270 mutants, is split into
  sixteen shards, three survivors gained tests, and a flaky Burrmill session count was fixed.
- **The PR reviewer sees the code around each hunk**, and a finding below certainty 50 is posted as a
  note (#2666). Three RustSEC advisories against actix-http and actix-web, reached only through
  `feldera-types`, were cleared by a lockfile bump (#2756).

## Compatibility and upgrade

Replace the binary and restart. A 5.17 store is used as it is. Of the nests listed at the top, only one
with a `function` event parameter (#2694) must re-index; a nest named for an unlisted chain is
refused until it is renamed (#2686); the others get a new NID and keep their data. A failover deployment upgrades writers before followers, as for 5.17. A client
reading a mount's `/metrics` under strict isolation for runtime-wide series should read the root
`/metrics` instead.

What 5.18 does not fix: `object_store` has no conditional delete, so a prune on a store configured
without conditional writes now stops rather than racing, and its zero-byte tombstones stay.
